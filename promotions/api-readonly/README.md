# Isolated TEST API reader

Deploy only `Adapter.gs`, generated `Reader.gs`, and `appsscript.json` to the separately approved TEST Apps Script API executable. Never replace the existing web-app script or its project. `Reader.gs` is an explicit function closure copied verbatim from `../Code.gs`; repair audit validators are retained to read existing events, but no repair application or business writer exists here. Regenerate with `node promotions/api-readonly/build.mjs`; verify drift with `--check`.

Public entry points:

- `readPromotions(envelope)`: API `scripts.run` parameters contain one existing signed TEST envelope object. Only exact `bootstrap` and `readStudent` requests are accepted. Authenticated requests return the same five-field confirmation (`bridge`, `target`, `installation`, `requestNonce`, `result`) as the existing web app, directly as an API return value. Failed bridge authentication returns the existing bare authorization denial. All promotion, repair, registration, correction and `checkSave` requests reject before any workbook read.
- `configureTestReader(config)`: owner-only configuration setup. First privately pin `TEST_OWNER_EMAIL`, `TEST_WORKBOOK_ID`, and `TEST_BRIDGE_ORIGIN` in this new script; the origin is the authorized PR86 route. Pass exactly those three values plus `TEST_BRIDGE_SECRET`, `TEST_BRIDGE_MODE` (`m1-authorized-tablet-test-v1`) and `TEST_BRIDGE_INSTALLATION` (`rev`) through the approved private server initialization flow. This function verifies the owner, pins and prepared TEST workbook, then sets only secret/mode/installation under a lock. It returns only `configured` or `already_configured`; it refuses any different existing configuration. Do not expose the secret in browser code, logs, source or this document.

The manifest restricts execution to `MYSELF`. Native `SpreadsheetApp` uses the existing full `spreadsheets` service scope plus `userinfo.email`; read-only behavior is enforced by the physically restricted code and operation validation, **not** by an OAuth read-only grant. Configuration changes are limited to the new script's approved properties. The only routine request write is its own 180-second nonce cache. No LIVE properties, data or writer route are used.

The new script's lock and nonce cache are separate from the existing writer's. They protect this adapter's replay check, not a cross-project transaction. Strict history validation rejects incomplete or inconsistent snapshots; results reflect the authoritative rows read during that request. Fresh server envelopes remain mandatory. This artifact does not migrate the existing write path or claim delivery reliability before the hosted proof.
